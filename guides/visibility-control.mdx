---
title: "Visibility control"
description: "Show or hide individual mesh objects per step to focus the viewer on the components relevant to each assembly step."
---

Visibility control lets you specify which 3D objects in the scene are visible when the viewer is at each step. Objects hidden for a step are removed from the render so users focus on the components being assembled.

## How it works

Each visibility assignment links a step to a mesh object and marks it as included or excluded:

```typescript
interface StepObjectVisibility {
  stepId: string;   // ID of the timeline step
  objectId: string; // Name or identifier of the mesh object in the GLB
  included: boolean; // true = visible, false = hidden
}
```

At runtime, the viewer reads the visibility assignments for the current step and toggles object visibility accordingly.

## Object identifiers

`objectId` corresponds to the name of a mesh node in the GLB scene graph. You can find node names in Blender's **Outliner** panel or by using a glTF inspection tool.

<Tip>
  Name your mesh objects clearly in Blender before exporting (e.g. `frame_left_arm`, `flight_controller`, `battery_pack`). Descriptive names make visibility assignments easier to manage in the dashboard.
</Tip>

## Assigning visibility in the dashboard

1. Select a step in the timeline editor.
2. Open the **Visibility** panel from the floating toolbar.
3. The panel lists all mesh objects in the scene.
4. Toggle each object to **Shown** or **Hidden** for the current step.

Objects with no explicit assignment for a step inherit the default visibility from the model — typically all objects are visible unless you override them.

## Visibility assignments and drafts

Visibility assignments are part of the project draft. They are saved alongside timeline steps when you click **Save**. The draft payload includes a `visibilityAssignments` array with one entry per `(stepId, objectId)` pair that has an explicit override.

Objects not listed in `visibilityAssignments` for a given step retain their default GLB visibility state.

## Validation

When a draft is saved, the server validates visibility assignments:

- Only assignments referencing valid step IDs (from the current `timelineSteps` array) are retained.
- Assignments with empty or missing `objectId` values are discarded.
- Assignments without a boolean `included` value are discarded.

<Warning>
  If you delete a step, all visibility assignments for that step are automatically removed on the next save.
</Warning>
