---
title: "API overview"
description: "REST API for managing viewer projects, drafts, releases, assets, and manifests."
---

The Animator Dashboard exposes a REST API for programmatic management of viewer projects. All endpoints return JSON and use standard HTTP status codes.

## Base URL

All API endpoints are relative to the base URL of your dashboard deployment:

```
https://{your-dashboard-host}
```

## Authentication

API requests require a valid session cookie obtained by authenticating through the dashboard. The session is validated server-side on every request.

Endpoints are protected at two access levels:

| Level | Who can access |
|-------|---------------|
| `editor` | Users with editor or admin membership on the project |
| `admin` | Users with admin membership on the project only |

Requests without a valid session return `401 Unauthorized`. Requests with a valid session but insufficient permissions return `403 Forbidden`.

## Response format

All responses use the following envelope:

```json
{
  "success": true,
  "data": { ... }
}
```

On error:

```json
{
  "success": false,
  "error": "Human-readable error message."
}
```

## Pagination

List endpoints support cursor-based pagination. Pass a `cursor` query parameter with the `nextCursor` value from the previous response. When `nextCursor` is `null`, you have reached the last page.

```
GET /api/admin/viewer-projects/{companyId}/{productId}?action=releases&limit=20&cursor={nextCursor}
```

Default page size is `20`. Maximum page size is `100`.

## Rate limits

Some endpoints are rate-limited to prevent abuse. When you exceed the limit, the API returns `429 Too Many Requests` with an error message.

| Endpoint | Limit |
|----------|-------|
| Create preview | 5 requests per minute per project |
| Deploy live | 3 requests per minute per project |
| Asset upload intent | 20 requests per minute per project per user |

## Error codes

| HTTP status | Meaning |
|-------------|---------|
| `400` | Bad request — missing or invalid parameters |
| `401` | Unauthorized — no valid session |
| `403` | Forbidden — insufficient permissions |
| `404` | Not found — project, release, or asset does not exist |
| `405` | Method not allowed |
| `409` | Conflict — draft revision mismatch (see `DRAFT_CONFLICT` code) |
| `429` | Rate limit exceeded |
| `500` | Internal server error |

### Draft conflict

When saving a draft, you must pass the `expectedRevision` matching the current revision number. If another client has already saved a newer revision, the API returns `409` with:

```json
{
  "success": false,
  "error": "Draft revision mismatch.",
  "code": "DRAFT_CONFLICT",
  "currentRevision": 7
}
```

Fetch the latest draft, merge your changes, and retry with the updated `expectedRevision`.
